# 法奥控制器仿真验证：待执行，不是测试通过报告

## 运行前只读预检
运行 `python tests/sim_validation/preflight.py` 查询宿主机，不安装软件、不更改路由、不接触机械臂。结果仅表示运行时线索，不代表能够部署或已经完成仿真。不要提交包含当前机器详情的JSON结果。

官方 3.8.2 Docker 文档要求 Ubuntu 18.04.6、4 GB RAM、50 GB存储、6核，采用 root、privileged 和自定义桥接网络。不能将当前环境视为部署完成。官方默认仿真IP为192.168.58.2，允许修改IP；用户目标192.168.57.2必须显式配置，不能混淆。

## 进入测试前的条件
- 获取用户 SDK 的确切版本、目标控制器版本、匹配的 SimMachine 版本，保存来源与 SHA256。不得以 latest 自动替换。
- 当前附件 SDK 的20003/20004/8080只是已分析版本的证据，不是所有版本通用承诺。
- 仅在隔离测试宿主机运行，不能连接物理机械臂网络；高权限镜像不得直接接入用户日常主机/公司网。
- 先确认磁盘与CPU内存、虚拟化与镜像获取权限；下载页能列出文件不等于已经下载或验证镜像。

## 目标拓扑与验收证据
B控制电脑 → A转发电脑 → 模拟机械臂192.168.57.2。B只接电脑侧网络，不能直接接机械臂网段，否则测试会绕过A。

1. 在隔离环境做直连基线：使用匹配 SDK 的版本查询、状态读取，记录原目标 IP、SDK返回值与完整版本，不运行用户附件运动示例。
2. 在B继续使用原目标IP，检查20003/20004/8080多通道连接和状态持续更新。TCP握手成功不能代替SDK协议测试。
3. 保存B/A路由、A转发/NAT配置、两侧抓包、各端口连接与返回值。确认B流量确实经过A，且模拟机械臂回包到达B。
4. 分别断开电脑侧/机械臂侧模拟连接，验证超时、错误提示、恢复和不会重复执行命令。
5. 对比直连与转发结果。只有上述路径与SDK响应都有证据，才标为“模拟控制器原IP多端口验证通过”。
6. 另行进行Windows真实界面、小屏/缩放/键盘操作与真实双机只读验证。仿真不能证明真实运动、力控制、急停或现场安全。

## 本地传输对照（不是控制器仿真）
`python tests/sim_validation/three_ports.py` 只在 127.0.0.1 上临时启动 20003/20004/8080 三个 echo 服务，25轮并行发送/回读，校验数据完整性。端口被占用会报错，不终止其他程序。每轮设置15秒超时，最后关闭监听。
这不加载厂商 SDK、不模拟机器人协议，也不通过 A 的真实路由/NAT。不能将输出 PASS 当作项目端到端通过。

`python -m unittest discover -s tests/sim_validation` 验证预检不会把“发现虚拟化程序”误报为仿真通过。
