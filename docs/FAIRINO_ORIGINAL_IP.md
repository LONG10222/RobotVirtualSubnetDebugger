# 法奥 SDK 原 IP 连接配置

本页基于所提供培训资料、C++示例及配套库的静态检查，不是机器人实机验收。

## 已知连接要求

- 两份示例调用 `FRRobot.RPC("192.168.57.2")`，参数为机器人目标IP。
- 配套Debug与Release库静态显示客户端主动连接同一目标的TCP 20003（XML-RPC）、20004（状态）、8080（指令）。这不是一项单端口代理任务。
- 资料里的用户网口为192.168.57.2，示教端口另为192.168.58.2。应以实际控制器接口配置为准。
- 配置教程把电脑也设为192.168.57.2，若机器人保留该地址会冲突。A机械臂侧必须使用同网段另一个未占用地址，不能与机器人同IP。

## 软件内准备步骤

高级设置页“填入法奥资料参数（未保存）”仅编辑预览，不保存、不应用网络设置、不运行SDK。它将目标IP填为资料示例57.2、目标端口填为主RPC端口20003，开启路由/NAT规划并关闭单端口TCP代理。界面提示另外两个SDK端口；20003不是全协议端口清单。

此按钮不猜测、不更改A/B互联IP、A机器人侧实际地址或配对密钥。请先核对现场配置，再分别填写A/B角色和接口地址。保存配置也不等于已应用路由，应用步骤仍需独立审阅。

架构：B保持原代码中的目标57.2，通过57.2/32精确路由指向A的互联地址；A双网口转发并源NAT，机器人IP不变。A-B互联网段必须与机械臂网段不重叠。现有计划会拒绝电脑/机器人同IP、重叠网段、出口不唯一等危险配置。

普通localhost单端口代理不能让不改代码的SDK自动连接原IP；配对密钥也不会自动保护Route/NAT流量。当前尚未实现转发级端口授权过滤。

## 安全验收顺序

提供的JOG与MoveCart示例会移动机器人，不能用作第一次连通性测试。应先单独验证只读SDK状态查询，检查所有返回码。机器人使能、速度和运动指令必须与现场安全条件分开处理。

已执行的验证是生产配置逻辑与离线构建；没有运行SDK附件、没有改系统网络、没有让机器人运动。真实SDK多端口通信、Windows双PC路由/NAT、回连/固定源地址需求仍待现场验证。

## macOS 边界

所提供SDK为Windows x64/VS2022，示例使用windows.h与Sleep。当前没有macOS原生供应商SDK。Mac版应用的界面/基础代理兼容性不能替代这套Windows库的兼容性，需要供应商对应SDK或独立Windows控制端设计。
