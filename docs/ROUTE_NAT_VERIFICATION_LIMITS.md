# 原 IP 路由/NAT：验证与安全边界

## 当前行为

- B 只对机器人目标 IP 添加 `/32` 路由，下一跳为 A 的互联 LAN IP。
- A 启用互联与设备网卡的 IPv4 转发，WinNAT 的内部源范围是整个互联 LAN 网段。
- 这不是二层桥接：不承诺 ARP/广播发现、固定本地 bind 地址或回调连接兼容。
- 共享密钥仅用于应用代理协议。直接路由/NAT 的数据包不会经过该认证。
- 当前没有仅允许 B 身份或指定机器人端口的转发防火墙。其他互联 LAN 主机可能通过 A 转发；不能把 `/32` 客户端路由当成 A 的访问控制。只能在已隔离且可信的实验网络测试，不能在公共/校园共享 LAN 当作安全生产方案部署。

## 本轮修复

1. 标准点分十进制 IPv4 校验，拒绝整数、十六进制、缩写或带前导零的地址，避免字符串冲突检查被同地址别名绕过。
2. 原 IP 模式不再检查或自动改动未使用的代理 TCP 监听端口。发现端口检查保留，但这不是机器人端到端检查。
3. B 应用 `/32` 前检查所有活动接口的同目标前缀，非唯一匹配预期网卡/下一跳就拒绝，不删除 VPN 或其他程序的路由。创建前重复检查。竞态和实际 Windows 选路仍需实测。
4. 预览、确认窗口、NAT 步骤描述及导出脚本明确显示上述认证和范围限制。

## 本轮测试证据

- Linux 上 70 项配置、视图模型、事务、锁与生成脚本断言通过。没有执行任何系统网络配置命令。
- Windows WPF 交叉编译 0 警告、0 错误；没有启动 GUI。
- 新增 `tests/route-preflight-mocks.ps1`，运行生成的只读 guard，对空路由、正确路由、其他网卡冲突、错误下一跳、并行/重复路由、无关路由、读取失败作隔离 mock。已接入 Windows CI；本地无 PowerShell，未在本地执行。

## 必须实际验证，不能由上述测试替代

- Windows 双机真实路由/WinNAT 数据路径、默认路由与 VPN 共存、回滚。
- 对比 A 直连与 B 经 A 访问同一版本虚拟控制器，三个 SDK 端口同时连接、只读状态与断线恢复。
- 未授权第三台主机能否转发，如何在现场提供真正的隔离与访问控制。
- 真实机械臂只读连接。所有运动测试应另行在有急停和人员现场监护的条件下进行。
